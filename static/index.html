Source

ERA5 is produced by the European Centre for Medium-Range Weather Forecasts (ECMWF) for Copernicus, the European Union's Earth observation programme. It is free to use.

How it is made

Millions of observations from weather stations, balloons, aircraft, ships and satellites are combined with a weather model, which fills the gaps between them. The result has a value for every hour and every place on Earth since 1940. This kind of dataset is called a reanalysis.

Collection

The data was downloaded through Open-Meteo, a free weather API. Every file was validated before it was saved: a complete time axis, no missing values, and all values within physical limits.

Limits of the data

Each point represents a grid square, about 9 km wide for the hourly data and about 28 km wide for the record since 1940. The values are smooth and complete, but can differ from a single weather station in the city.

What was measured every hour

  • Temperature
  • Humidity
  • Dew point
  • Air pressure
  • Wind speed
  • Wind direction
  • Cloud cover
  • Rain and snowfall
  • Snow on the ground
  • Sunlight

All ten are continuous numeric variables. Each day is summarized into 17 values per place, such as the daily mean, minimum and maximum temperature and the 24 hour change in pressure. Wind direction is circular (359° and 1° are neighbours), so it was converted into a north and an east component. No scaling or normalization was needed, because decision trees only compare values against thresholds.

Choice of places

Weather in Mongolia mostly moves from west to east, so the places were chosen along that path: Khovd in the far west, Uliastai, Mörön in the north west, and Ulaanbaatar. Cold air that crosses them in turn gives the model advance warning.

Adding places has a cost. Each place adds 17 values per day, while the dataset has 16,764 days. With too many features relative to the number of examples, a model starts fitting noise. The free API also limits how much data can be downloaded.

The model also uses one place across the northern border, Irkutsk in Russia, to capture cold air arriving from Siberia.

How it works

The project follows the knowledge discovery (KDD) process, from raw data to an evaluated model.

  1. 1

    Selection

    Hourly weather for Ulaanbaatar and the places upwind of it, 1980 to 2025.

  2. 2

    Preprocessing

    Validation of every file, complete days only, hourly values summarized into 17 daily values per place.

  3. 3

    Transformation

    The normal is subtracted to give the anomaly, then lags, rolling averages and upwind differences are added: 158 features.

  4. 4

    Data mining

    Feature selection, then CatBoost gradient boosting, one model for each day ahead.

  5. 5

    Evaluation

    Hold-out test on 2023 to 2025, comparison with baselines, error analysis and SHAP explanations.

Why predict the anomaly?

The seasonal cycle is known in advance. Removing it lets the model focus on the part that is hard to predict: whether the coming days will be warmer or colder than usual. The normal is added back at the end.

Why use upwind places?

Weather in Mongolia mostly moves from the west and north. Conditions over Khovd or Mörön today often reach Ulaanbaatar one to three days later, which gives the model useful lead time.

Gradient boosting

Gradient boosting is an ensemble of many small decision trees. Unlike bagging, where trees are trained independently and averaged, boosting trains them in sequence: each new tree is fitted to the errors left by the trees before it.

How each tree is grown

A regression tree chooses the split that reduces the squared error the most, the regression counterpart of information gain or Gini impurity in classification. CatBoost grows symmetric trees, where every node on a level asks the same question, which keeps each tree simple.

Model

Three CatBoost regression models, one for each day ahead. Each predicts how far the day's mean temperature will be from normal.

Model card

The main facts about the deployed model.

Data split

A hold-out split by time. Random splits and k-fold cross validation would place almost identical neighbouring days on both sides and overstate accuracy, so every model is tested on later years than it learned from. Three days are removed at each border so no target crosses into the next part.

Model selection

Three gradient boosting libraries on the same data with default settings. Mean validation RMSE in °C over the three days, lower is better.

Feature selection

Two stages. A filter method first removed 32 near duplicate features (correlation above 0.95). A wrapper style step then ranked the rest by permutation importance on the validation set, and the curve below shows the error when only the top N are used. The error stops improving at about 40, so 40 of 158 were kept.

Hyperparameter tuning

Tuning improved the validation error slightly. For longer lead times the search chose much stronger L2 regularization, probably because day 3 is noisier and easier to overfit.

Explainability (SHAP)

Mean absolute SHAP value of each feature on 2023 to 2025: how much it moves the forecast on average. The list shows the ten most important features from the four Mongolian places.

Leakage checks

Leakage happens when information about the answer reaches the model during training. Scores then look better than real forecasts will be. These checks prevent it.

  • Time split with gaps. Training, validation and test never overlap, and three days are removed at every border.
  • Past data only. Every feature for a day uses weather up to the end of that day. An automated test replaces all later weather with random numbers and confirms that no feature changes.
  • Normals from training years only. The normal temperature curve was fitted on 1980 to 2019, never on validation or test years.
  • Locked test set. The test years were scored once. A fingerprint of the models is stored, and evaluating any different model on the test set is refused.
  • Same code in training and live use. The website builds features with the same function as training, and a test confirms both produce identical values.

Known limitations

  • Reanalysis, not station data. ERA5 is a reconstruction on a grid, so it can differ from a single weather station in the city.
  • A few hours of hindsight. ERA5 evening values already include some observations from the next morning. The measured effect is at most 0.17° on the 1 day score. The live forecast does not have this effect.
  • Repeated use of validation data. Feature selection, model selection, tuning and early stopping all used 2020 to 2022, so validation scores are slightly optimistic. The test score is the unbiased estimate.
  • Cautious in unusual weather. A model trained to minimize squared error tends to predict values closer to normal during rare warm or cold spells.
  • Daily mean only. The model forecasts the daily mean. 12 PM and 8 PM add that day's swing from the weather service's forecast and are not separate model forecasts.
