Source

Made by the European Centre for Medium-Range Weather Forecasts (ECMWF) for Copernicus, the EU's Earth observation programme. Free to use.

Collection

Downloaded through Open-Meteo, a free weather API (a website that sends data to programs).

Every file was checked before saving: no missing hours, no empty values, no impossible values.

What was recorded every hour

  • Temperature
  • Humidity
  • Dew point
  • Air pressure
  • Wind speed
  • Wind direction
  • Cloud cover
  • Rain and snowfall
  • Snow on the ground
  • Sunlight
  • Each day's 24 hours are summed up as 17 values per place, such as the average, lowest and highest temperature.
  • Wind direction is split into a north part and an east part, so that 359° and 1° count as neighbours, which they are.
  • No scaling needed: a decision tree only asks "is this value above or below a limit?", so units do not matter.

How it works

The project follows the five steps of the knowledge discovery (KDD) process, from raw data to a tested model.

  1. 1

    Selection

    Choose the data: hourly weather for Ulaanbaatar and four places to the west and north, 1980 to 2025.

  2. 2

    Preprocessing

    Clean it: check every file, then sum up each day's 24 hours as 17 values per place.

  3. 3

    Transformation

    Make clues: subtract the normal (the anomaly), then add past days, averages and differences between places: 158 features.

  4. 4

    Data mining

    Learn: keep the 40 best features, then train one CatBoost model for each day ahead.

  5. 5

    Evaluation

    Check: test on 2023 to 2025, compare with simple guesses (baselines), and see what the model relies on (SHAP).

Why predict the anomaly?

  • Everyone already knows January is cold and July is warm.
  • So the model only predicts the hard part: how much warmer or colder than normal (the anomaly).
  • The normal is added back at the end to give the temperature.

Why use upwind places?

  • Weather in Mongolia mostly travels from the west and north.
  • What happens in Khovd or Mörön today often reaches Ulaanbaatar 1 to 3 days later.

Gradient boosting

  • An ensemble (a team) of many small decision trees, built one after another.
  • Each new tree fixes the mistakes the earlier trees still make.
  • Different from bagging (for example a random forest), where trees are built separately and then averaged.

How each tree is grown

  • A tree asks yes or no questions, for example "was yesterday more than 3° colder than normal?"
  • Each question (split) is chosen to make the squared error as small as possible: the regression version of Gini impurity or information gain.
  • CatBoost trees are symmetric: every branch on the same level asks the same question.

Model

Three CatBoost models, one for each day ahead. Each predicts how much warmer or colder than normal the day will be.

Model card

The main facts about the model running on this website, in one place.

Data split

  • Split by time, never at random: neighbouring days are almost identical, so a random split would make the model look better than it is.
  • Training: the model learns. Validation: choices are made. Test: the final exam, used once. Every model is tested on later years than it learned from.
  • 3 days are left out at each border, so no answer leaks into the next part.

Model selection

Three gradient boosting libraries, same data, default settings. Validation error (RMSE, the typical miss in °C): lower is better.

Feature selection

  • Filter: 32 features that were near copies of others were removed (correlation above 0.95).
  • Ranking: each remaining feature was shuffled on the validation years to see how much worse the model gets (permutation importance).
  • Kept: the top 40 of 158.

After about 40 features the error stops improving, so the smaller, simpler model was kept.

Hyperparameter tuning

A small improvement, because CatBoost's defaults were already good. Day 3 got a much stronger L2 brake (regularization), likely because it is noisier and easier to overfit (memorise).

Leakage checks

Leakage means the model secretly sees the answer while learning, so its score looks better than a real forecast would be. Five checks make sure this does not happen:

  • Time split with gaps. Training, validation and test years never overlap.
  • Past data only. A test replaces all future weather with random numbers, and no feature changes.
  • Normals from training years only. The normal curve was fitted on 1980 to 2019 only.
  • Locked test set. Scored once. Testing a different model on it is refused.
  • Same code live and in training. A test confirms the website builds exactly the same features.

Confusion matrix (three groups)

Each test day is put into one of three groups: colder, near or warmer than normal (borders taken from the training years). Rows: what really happened. Columns: what the model predicted. The diagonal shows the correct days. Precision: how often a prediction of that group was right. Recall: how many real days of that group were found.

Known limitations

  • Reanalysis, not station data. Each value covers a grid square, so it can differ from the city's weather station.
  • A few hours of hindsight. ERA5 evening values include some next-morning observations. This makes the 1 day score look at most 0.17° better.
  • Validation used many times. All choices were made with 2020 to 2022, so the test score (2023 to 2025) is the fair one.
  • Cautious in unusual weather. During rare very warm or very cold spells, forecasts stay closer to normal than reality.
  • Daily average only. The model's 12 PM and 8 PM values are its day average plus that hour's difference, not separate forecasts.
